# Environment quality gates

This document defines the evidence required before the environment is considered ready.
All numbers and receipts below must be generated from this repository.

## 1. Solvability
- Gold solution scores 1.0 on every validated instance.
- A differently structured correct solution also scores 1.0.
- Any failures are recorded with diagnostics.

## 2. Baselines
- Untouched environment scores below 0.20.
- Familiar or prior solution passes visible checks but scores low on hidden checks.
- Public-feedback overfitting does not transfer to hidden evaluation.

## 3. Verifier integrity
- Reward is computed only from canonical ground truth.
- Agent self-reports are ignored.
- Test, configuration and grader tampering cannot affect canonical scoring.
- Every scored objective is independently load-bearing.

## 4. Long-horizon qualification
- 15–30+ causally linked actions are required.
- Multiple heterogeneous tools are necessary.
- State transitions constrain later actions.
- Failure detection and recovery are unavoidable.

## 5. Reward signal
- Reward is graded across independent objectives.
- A weak-to-strong solution ladder is monotonic.
- Mean reward and strict pass rate are reported separately.

## 6. Cheat battery
Each control must record:
- whether it executed,
- whether the intended exploit path was reached,
- reward,
- fatal/import error,
- timeout status,
- expected outcome.

Required controls include:
- visible-feedback overfitting,
- oracle import,
- hidden-file reads,
- configuration tampering,
- test editing,
- constant/stub output,
- timeout/resource abuse,
- state-transition bypass.

## 7. Runtime isolation
- Oracle, gold, generator and hidden assets are absent from the agent runtime.
- Import and direct filesystem probes fail under the agent identity.
- Network and process visibility are tested and documented.
- Runtime transcripts are saved as receipts.

## 8. Reproducibility
- Generation is deterministic from namespaced seeds.
- Train and evaluation seed spaces are disjoint.
- One command regenerates all offline receipts.
- Documentation values are generated from saved evidence.

## 9. Statistics
- Every rate includes its sample count and confidence interval.
- Runs with fewer than 12 tasks are labelled as smoke tests.
- False accepts and false rejects are reported separately.

## 10. Known limitations
Any unverified property or incomplete calibration is named explicitly.
